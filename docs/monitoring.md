# Ежедневный мониторинг сайта

Каждое утро в **08:00 по Москве** GitHub Actions запускает проверку боевого сайта
`https://melnikov-mebel.netlify.app` и присылает сводку в Telegram (бот уведомлений,
секреты `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — те же, что для уведомлений о сбоях CI).

## Что проверяется

| Проверка | Как |
| --- | --- |
| Сайт открывается | Запрос к сайту, ожидается ответ 200 |
| Бот формы заявок жив | Запрос `getMe` с токеном `VITE_TELEGRAM_BOT_TOKEN` |
| Фото не «битые» | Playwright проходит всю страницу и проверяет каждую картинку |
| Контакты на месте | Телефон `+7 905 771 6340` и ссылка на Telegram сверяются с эталоном в `monitoring/site.checks.ts` |
| Форма доставляет заявки | Playwright отправляет тестовую заявку «ТЕСТ — автопроверка сайта»; успех засчитывается, только если Telegram подтвердил доставку |
| Скорость загрузки | Lighthouse, тревога при оценке ниже 80/100 |

## Как читать сводку

- «✅ … всё в порядке» — ничего делать не нужно. Само наличие утреннего сообщения тоже
  проверка: если сводка не пришла — сломался сам мониторинг, загляните в Actions.
- «⚠️ … ЕСТЬ ПРОБЛЕМЫ» — в сообщении отмечено, какая проверка упала, и есть ссылка на логи.
  Скриншоты упавших проверок сохраняются как артефакт `monitoring-screenshots` в запуске.

## Важно знать

- Каждое утро в ваш Telegram-чат заявок будет приходить **тестовая заявка** с именем
  «ТЕСТ — автопроверка сайта» — это норма, перезванивать не нужно. Она же появляется
  в Netlify → Forms.
- Запустить проверку вручную: **Actions → Daily Monitoring → Run workflow**.
- Если телефон или Telegram-контакт на сайте поменяются, обновите эталонные значения
  в начале файла `monitoring/site.checks.ts`, иначе проверка контактов начнёт падать.
- Время запуска и порог скорости меняются в `.github/workflows/daily-monitoring.yml`
  (поля `cron` и число `80`).
